## 📊 文件命名规范

### 1. 统一格式
- **所有图片**: `step_XXXX.png` (四位数字，PNG格式)
- **子任务标识**: `1a`, `1b`, `2a`... (数字+字母)
- **全景图**: `{phase}_panorama_{direction}.png`

### 2. Step编号规则
```
step_0001 ~ step_0012    → 初始环视（12步）
step_0013 ~ step_0024    → 子任务1a执行
step_0025 ~ step_0036    → 验证子任务1a（12步）
step_0037 ~ step_0048    → 子任务1b重试（如果验证失败）
...
```

### 3. 子任务标识规则
- `1a`: 子任务1第一次尝试
- `1b`: 子任务1第二次尝试（验证失败重新规划）
- `1c`: 子任务1第三次尝试
- `2a`: 子任务2第一次尝试

## 🔄 图片读写路径映射

### 保存位置 (Writer)

| 模块 | 保存路径 | 文件名格式 |
|------|---------|-----------|
| `Visualizer.save_rgb()` | `rgb/` | `step_{step:04d}.png` |
| `Visualizer.save_detection()` | `detection/` | `step_{step:04d}.png` |
| `Visualizer.save_global_map()` | `global_map/` | `step_{step:04d}.png` |
| `Visualizer.save_local_map()` | `local_map/` | `step_{step:04d}.png` |
| `NavigationVisualizer.save_step_visualization()` | `visualization/` | `step_{step:04d}_{subtask_id}.png` |
| `PanoramaGenerator.create_panorama()` | `panoramas/` | `{phase}_panorama_{direction}.png` |
| `SaveManager.save_thinking()` | `thinking/subtask_{id}/` | `response.json` + `input_images/` |
| `SaveManager.save_action()` | `action/subtask_{id}/step_{X}/` | `response.json` + `input_images/` |

### 读取位置 (Reader)

| 调用位置 | 读取路径 | 用途 |
|---------|---------|------|
| `generate_initial_subtask()` | `panoramas/{phase}_panorama_*.png` | 输入给LLM的全景图 |
| `generate_initial_subtask()` | `global_map/step_0012.png` | 初始环视后的地图 |
| `verify_and_replan()` | `panoramas/verify_{id}_panorama_*.png` | 验证时的全景图 |
| `verify_and_replan()` | `global_map/step_{X:04d}.png` | 验证时的全局地图 |
| `execute_action_with_vlm()` | `rgb/step_{X:04d}.png` | 当前RGB图像 |
| `execute_action_with_vlm()` | `detection/step_{X:04d}.png` | 当前检测图像 |
| `execute_action_with_vlm()` | `local_map/step_{X:04d}.png` | 当前局部地图 |

## ✅ 路径一致性验证

#### 1. 环视建图后的地图引用

## 🎯 设计优势

### 1. 命名统一性
- 所有step使用`step_XXXX`格式，四位补零
- 所有图片使用PNG格式，无损压缩
- 子任务ID统一格式：数字+字母

### 2. 层级清晰
- 按功能分目录（rgb、detection、map等）
- 按子任务分组（thinking、action）
- 按尝试次数区分（1a、1b、1c）

### 3. 可追溯性
- 文件名包含step和subtask信息
- Summary按子任务ID分组
- 验证失败不会覆盖之前的数据

### 4. 易于调试
- 每个子任务的所有数据独立保存
- 输入图片完整保留
- 时间戳记录便于追踪

## ⚠️ 注意事项

1. **文件格式统一**: 所有图片必须使用`.png`扩展名
2. **路径使用**: 
   - 保存时使用`{step:04d}`格式化
   - 读取时使用相同格式
3. **子任务标识**: 
   - 完成时递增count，重置attempt
   - 失败时递增attempt，保持count
4. **环视Step**: 
   - 每次环视占用12个连续step
   - phase名称要包含在文件名中
