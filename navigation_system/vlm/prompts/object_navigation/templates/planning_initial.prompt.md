# Reasoning (4 Parts)

**1) 12-View Analysis (MUST analyze EACH IMAGE 1-12)**
**Format**: For each IMAGE, use `IMAGE# (Direction Angle°): likely [space]; NEAR: ...; FAR: ...; Obstacle: ...; Landmark: ...; Space Waypoint: ...`, omitting any field not visible there.
**Distance reading**: `Obstacle`, `Landmark`, and `Space Waypoint` refer only to that IMAGE's shown value; do not infer hidden values.
**Near rule**: treat only cues within about {arrival_near_m}m as truly NEAR/current-position evidence. This is for localization/progress only, not the benchmark success radius. Farther cues may support route choice or target-space inference but do not prove arrival.
**Evidence order**: read each IMAGE in this order: NEAR current/large objects + implied space; FAR objects/openings + implied adjacent space; obstacle distance + blocked/caution/passable; landmark + shown distance; reachable space waypoint + shown distance if explicitly shown. Judge RGB/layout first; labels/distances only support. Use all 12 views, openings, furniture relations, obstacle layout, and adjacent-view consistency—not one detection—to infer the current space, nearby connectors, likely target-related spaces, and the best search direction. Determine the current space from the **nearby current scene** first: dominant nearby furniture, fixtures, boundaries, and layout define the space type. Previous Space Waypoints / chains are visited-history only, not proof of where you are now. If nearby evidence shows you already entered a different space, update the current space name accordingly.
**No hallucination**: analyze each IMAGE separately. If an IMAGE shows only a wall or nearby furniture, say only that. Do not invent unsupported rooms, target-object evidence, landmarks, or space waypoint cues.
**Conclusion**: Identify from the 12-view content: Current Position Guess: [current space + NEAR landmarks + adjacent-view context] | Reachable Far Area/Landmark: [which IMAGEs show reachable FAR spaces/landmarks/openings, what each leads to, and which target-object search transition each may support] | Target-Space / Object Direction Guess: [which IMAGE/view most likely points toward the best current search direction, and why] | Blocked: [which IMAGEs have obstacle distance <{obs_blocked_m}m]

**2) Current Position + Global Task Goal + Task Chain**
1. Use the current observations together with the current area, nearby Space Waypoints, connected openings, explored map/trajectory, and obstacle layout as supporting evidence to determine the local spatial structure around the strict current anchor: which openings are true connectors, which spaces are only seen through openings, which directions are blocked/tight, and which branch is the safest forward search path.
2. Use that supporting structure to infer the most plausible immediate target-object search stage. If the target object itself is already credible/current, keep the search local and do not drift outward. If the current localized space has no credible target-object evidence, do not keep circling or micro-searching that same space; prefer the connector, doorway, room-entry anchor, stair/landing transition, or concrete cue that best advances toward a more plausible target-object space while staying navigable and exploration-efficient. Prefer promising unexplored target-relevant branches over generic open space; use floor transitions when the target hypothesis supports another level. Do not keep revisiting an already explored room/branch if current evidence and past exploration already suggest the target object is not there. If the current and known explored spaces show no target-relevant landmark/object evidence, prefer a passable unknown frontier: a view/opening whose bottom strip does **not** show a `space waypoint`, over returning to an explored Space Waypoint.
3. **Current Position**: infer where you are now from the current observations, using Space Structure and map only as supporting evidence. Write `current_waypoint` as `current space name - nearby landmark / nearby landmark / nearby landmark`. Infer the left-side space name from the current surrounding views, nearby objects, openings, and layout. The current space name must follow the nearby current scene, not the last visited waypoint label: previous Space Waypoints / chains only show where you have been. If nearby evidence shows you already crossed into a new room/area, rename the current space to that new concrete space type immediately. The right side must contain only nearby current cues. If the target object is already clearly beside you in the current views, include that target object after `-`.
4. **Global Task Goal**: copy the target object from the Global Task exactly. Then reason where that object is likely to be: the plausible supporting space, area, and local placement for searching. This is an object-search hypothesis from commonsense plus current evidence, not a confirmed route and not a room/proxy goal. If the localized current space is unlikely to contain the target, or it has no credible target-object evidence, plan toward the best connector or next plausible target-supporting space instead of staying in place.
5. **Task Progress start**: at task start, nothing is complete. Write `task_progress` as short object-search pieces with exactly one `(Current)` stage. The past/current part records only actual localized evidence; the future part is a plausible imagined search plan toward the target object.
6. **Task Waypoint Chain**: write the ordered search chain with full `space's landmark` nodes. Past/current nodes must be grounded in actual localization; future nodes may be imagined search hypotheses: current anchor `(Current)` -> best connector/area cue -> likely target-object space/area -> exact target-object anchor `(Goal)`. Keep it consistent with `current_waypoint` and `task_progress`.
7. **Task Goal Arrival Check**: do not stop in initial planning. Initial planning must always keep `global_landmark_arrival=false`, even if the target object is already visible or appears very close. Instead, if the exact target object is already the active final-stage destination, keep `next_waypoint` and `subtask_landmark` on that exact target object and output an approach/alignment subtask. Episode stop can happen only on a later verify call after at least one executed action subtask toward the exact target object.

**3) Subtask Destination + Direction + Subtask Instruction + Landmark**
1. From the strict current anchor and Part 2 spatial/task analysis, identify the immediate next search-stage destination. Advance one anchor at a time. Write `next_waypoint` as one full `space's landmark` node, not `space / object`, not a bare room, and not only the object name when the supporting space is known. If the target object is already clearly visible/credible and locally reachable, `next_waypoint` may be the target object anchor itself. Otherwise choose one connector, doorway, room-entry anchor, stair/landing anchor, or concrete cue that best advances toward the likely target-object space. Do not jump to a later generic space or unsupported room. Enter the final target-object stage by directly copying the Global Task target object into `subtask_landmark`. If a descriptive phrase is accidentally used, it must still contain the exact target object word/phrase; proxy/support objects do not count. `next_waypoint` or a guessed object mention alone does not start the final stage. In initial planning, even if the target object is already visible/current, keep this as an approach/alignment stage and do not stop yet.
2. Choose `next_waypoint_direction` from the provided IMAGE labels only. Confirm the current anchor and active search stage first, then compare all views and pick the view whose real content best matches that destination. Prefer the target-aligned view whose near foreground is traversable now. Favor promising unexplored target-relevant directions over merely open generic views. If the current space has no credible target-object evidence, choose the best exit/connector toward a more plausible target-supporting space rather than wandering inside the same area. If explored rooms/branches and labeled Space Waypoints look target-negative, prefer a passable direction whose bottom strip has no `space waypoint` as the unknown frontier. Revisit known waypoints only for recovery, the only connector, or newly re-supported evidence. Allow an upstairs/downstairs transition when it is the best supported search branch.
3. Write one short immediate `subtask_instruction` for that same current search stage only. Use the fixed structure `From IMAGE N (Direction Angledeg) view, start, ...`. Prefer either a direct approach form or a connector-then-approach form, depending on whether the current stage is local approach or entry-then-approach. If the target object is already visible/current, still use a concise approach/alignment form and do not stop in initial planning.
4. Choose `subtask_landmark` only for the current stage. Prefer the target object itself if visible and useful; otherwise use one concrete visible cue that helps execute the chosen stage. Do not use a broad room label when a more concrete cue is available.

**4) Plan**
1. **Short-term Plan**: define the next executable subtask from the strict current anchor to the next selected Space Waypoint / search-stage anchor. Explain why `next_waypoint`, `next_waypoint_direction`, `subtask_instruction`, and `subtask_landmark` are the correct immediate move. This should be the next reachable connector, entry, local object cue, stair/landing transition, or target-object anchor if the final object is already locally reachable. State why other visible directions are weaker, generic, repetitive, less navigable, or already explored-and-target-negative.
2. **Long-term Plan**: use the explored Space Structure explicitly: Space Waypoints, Space Waypoint Chain, map/trajectory, floor/level context, landmark history, and object-space commonsense. Imagine and infer which space/area/local placement most likely contains the target object, then explain how to continue from the short-term subtask toward the exact target-object anchor. Summarize the forward search route as: current/next Space Waypoint -> connector/entry/floor transition -> likely target-supporting space/area -> exact target-object anchor. If the short-term subtask already reaches a valid target-object stop point, say to stop there. Never treat a proxy object as the final target.

**Sequential planning rule**:
- Output only the immediate next search stage/subtask. At task start, the task-start anchor is current. Localize first, build the Task Chain from current evidence, then choose the next destination. Prefer unexplored target-relevant branches over generic open space, and do not jump over required connectors/entries that are still supported by the current evidence. Stop only at the real target object anchor, not at a generic room or proxy landmark.
